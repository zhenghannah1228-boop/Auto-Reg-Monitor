## 一、数据字典 = `data/data_catalog.json`

这份清单登记了工具全部**监管性/事实性数据集**(纯 UI 配置不计),每个数据集含:

| 字段 | 含义 |
|---|---|
| `name` / `loc` | 名称 + 位置(哪个文件、哪个常量/JSON 路径) |
| `what` | 一句话说明这块数据是什么、驱动哪些视图 |
| `source` | 来源依据(EU/UN 原文、官方表、调研…) |
| `asof` | 数据时点基准 |
| `tier` | 置信度:`green` 原文核实 / `amber` 调研待核 / `gray` 待补充占位 |
| `trigger` | **何种事件发生时这块数据需要更新**(如某法规出新系列) |
| `edit` | **改哪个文件/常量、什么格式、改完怎么验证**(= 修改预留位) |
| `notes` | 已知缺口 / 置信度说明 |

**要改数据,先查这份清单对应条目的 `edit` 字段**,照着改;改完更新该条目的 `asof`/`tier`。

## 二、内部「数据状态」视图

主控台带一个数据状态台账页(左侧导航「25 数据状态·内部」),把上面这份清单渲染成表(置信度徽标 + 距 as-of 天数时效提醒)。

- **定位**:主控台(index.html)是团队**内部监控台**,此页即在其侧栏;客户端评估工具(E-mark / 网安 / 智驾 / 电气)**不含此页**,不会暴露给客户。
- 距 as-of 超 ~180 天(半个 WP.29 周期)的数据集会标黄提醒复核。

## 三、置信度红线(交付使用须知)

- 🟢 **原文核实**:已对照 EU/UN 官方原文逐条核对(含系统性车型编码审计),可直接采信。
- 🟡 **调研待核**(当前 2 个:`EMARK_ACCEPT` 采信国家清单、`cert_pyramid` 关税/采信):网络调研/二级来源,**交付给客户前建议由认证专家复核**;关税均为参考值(以海关最新税则为准)。
- ⚪ **待补充**(`REG_LINKS` 法规链接占位):接入法规库 URL 时填。

## 四、数据更新的两条通道

1. **法规雷达**(主控台 tab 19):AI 联网扫录 → 人工确认 → 入库,面向**外部新发布**监管信息。
2. **数据状态台账 + 本清单**:面向**工具自身内嵌数据**的时效维护;涉及更新时由维护方(Claude)主动预警,按 `edit` 字段落地。

## 五、非功能需求(交给开发实现)

- 评估结果目前只存浏览器 `localStorage`(各工具独立 key),换设备/团队不共享 —— 建议持久化到后端(主控台已有 Supabase)。
- 缺自动化 CI:现有回归脚本 `tools/verify_reg_data.mjs`(Playwright,27 项断言),建议纳入 CI。
- 单文件 2000+ 行,建议按模块拆分组件化。
- 目前仅中文、无移动端适配。
