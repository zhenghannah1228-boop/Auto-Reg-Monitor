## 二、2026-07-30 已修复:二期特有服务器逻辑 bug

以下为**一期没有、二期新增的服务器化逻辑**中的缺陷,属可直接修复的实现 bug(非业务规则),本轮已修:

1. **[中] 导入部分失败仍会删旧数据 → 净数据丢失**(`syncImport`)。
   原实现:①写库 try(upsert `regulations` + `import_logs` + 快照)失败只 toast;②紧接的「按国家替换式导入」
   删除块是**独立 try**,**不管写库成功与否都会执行**。若 upsert 因网络失败(新数据没入库),用户仍会看到
   删除确认框,一旦确认 → 库内既有旧记录被删、而新数据没写成,**净丢失**。
   **修复**:引入 `imported` 成功标志,删除分支加 `if(imported&& …)` 守卫——写库失败则**不进入删除**。
2. **[低] 「上一份快照」基准在同秒并列时选择不确定**(`refreshSnapshots`)。
   原按 `order=created_at.desc` 取 `snapshots[1]` 作对比基准;同一秒两份快照时排序不稳定。
   **修复**:排序追加 `,id.desc` 兜底,保证确定性。

修复后 Playwright 载入 `index.html` 零(非网络)JS 报错。

## 三、按 §7 留痕:一期疑似 bug,待业主确认后再改(勿静默修改)

以下项**一期源码本身即如此**,二期忠实照搬;属疑似逻辑 bug 但涉及业务规则,依 §7 **记录待确认,不擅改**:

1. **部分 ≤3 字母大写缩写的 KW 兜底正则缺 `\b` 词边界**(一期 `410-421` / 二期 `1231-1242`):
   已带 `\b` 的:`ADR\b`/`TIS\b`/`RED\b`/`IRA\b`/`VIN\b`/`COC\b`。**缺 `\b`、有误匹配风险的**:
   - **`OTA`(网络安全维度,带 `/i`)** —— 会命中 **"Toyota" / "quota"**,是最实的误报点;
   - `EMC` / `ELV`(可被 "shELVes" 命中)/ `ZEV` / `AEB`。
   影响:极少数法规名/备注含上述子串时,可能被误加维度标签(偏多计,非漏计)。
   **建议**:业主确认后对这些缩写统一加 `\b`;在确认前维持现状(与一期一致)。
2. **`nkAlias` 的「列名包含核心词」兜底可能极少数误取**(二期 `1636-1642`,一期无):
   二期新增的列名包含匹配层,理论上某列名恰含"备注"等核心词时可能误取;概率低,一并待确认。

## 四、本轮暂不处理(低价值 / 需并发测试,列为观察项)

- 多文件并行导入时 `import_logs.added_count` 计数可能偏多(仅展示,不影响入库正确性)。
- `sbFetchAll` 偏移分页在他人并发写入时理论可能漏 / 重(万级只读场景概率低)。
- `_batch`/`_impKeys` 无并发保护:首次导入未完成又触发导入,后一次覆盖前一批集合(低频)。

以上如需处理,建议专门做一轮多人并发导入测试后再动,避免无测试改并发逻辑引入新问题。
