# E-mark 合规评估工具 · 维护与变更说明

覆盖 `emark/emark_assessment.html`(EU 型批评估)与 `emark/cyber_assessment.html`(网安 & 功能安全评估)。本文件记录数据架构、维护方式、本轮变更与待办,供后续维护对照。

---

## 一、数据架构(重要)

### 1. 法规数据 = 单一权威源 `EU_ITEMS`
- **`EU_ITEMS`(130 项)是唯一权威源**,对应 EU 官方表 `2018/858 Annex II + 2019/2144 Annex I`(原文见 `docs/`)。字段:`{it, s 主题, r 法规, c 适用车型, im 强制实施日期, rno UN 编号(供 REG_META 查系列)}`。
- **Step 3「法规盘点」的 `ITEMS`(94 项)是子集**,其法规号在页面加载时由 `EU_ITEMS` **自动派生**(`toCompactReg()` 做格式归一:`UN Regulation No 21.01` → `UN R21.01`;`Regulation (EU) X, Annex Y` → `(EU) X Annex Y`)。
- **维护法规号只改 `EU_ITEMS` 一处**,Step 3 自动跟随,不会再出现两表不一致。`ITEMS` 只保留 Step-3 专有字段(`mark`/`tc`/`eif` 快照生效日/短名 `cn`)与 2 个汇总行(`G2-G12`、`GA1-GA22`)。

### 2. 版本/生效日的三个来源(`verCell()` 优先级)
1. **UNECE 活数据** `data/unece_status.json`(`as_of` 见文件)——`liveVersion()` 按 UN R 编号+系列匹配,显示「现行 <系列> · 生效 <日期>」。
2. **内置快照** `ITEMS.eif` / `REG_META[rno]`——活数据不可用或不在数据集时兜底。
3. **EU 框架/待定**——`EU_APPLY`(EU 委托法规 + 适用日)/`PENDING`(自动驾驶等细则待定项)。

### 3. 网安工具 `cyber_assessment.html`
- 四模块:R155 CSMS / R156 SUMS 就绪度 + 21434 CAL / 26262 ASIL 评级;侧栏「审计与导出」= ⑤ 审计就绪包(证据台账 + 风险登记册 + CSV 导出)。
- 跨页回显:向 `localStorage` 写 `emark_cyber_summary_v1`(v:2 契约:r155/r156 就绪度 + maxCal/maxA),E-mark 母工具 Step 4 的桥接卡读取显示。

## 二、法规准确性口径(红线)

- **只按原文标注,不臆造编号**。所有法规号/生效日均以 `docs/` 内 EU/UN 原文核对。
- **区分 UN R 与 EU 法规**:并非每项都有 UN R——牌照板空间、雨刮、挡泥板、ISA、酒精锁、DDAW、eCall、欧6/欧7 排放、空调 MAC 等是 EU 法规覆盖,UNECE 无对应 UN R。
- **生效日 vs 强制适用日**:UNECE 增补生效日(版本标注用)≠ EU 强制适用日((EU) 2019/2144 Art.16 + 附表 II 的 A/B/C/D 码日期)。

### 排放组法规归属(据 2018/858 Annex II + Euro7 2024/1257)
- 欧6(G 组):轻型 M1/M2/N1/N2 → `(EC) 715/2007`;发动机/重型 M3/N3 → `(EC) 595/2009`;空调 → `2006/40/EC`。
- 欧7(GA 组)→ `(EU) 2024/1257`,适用日 2026-11-29(M1/N1)/ 2028-05-29(重型)。**但三项不在欧7范围**:GA1 噪声 → `(EU) 540/2014`、GA13 回收 → `2005/64/EC`、GA14 空调 → `2006/40/EC`。
